🧱 MVC v/s MTV en Django, DRY y Plantillas

Django utiliza un patrón arquitectónico llamado **MTV (Model-Template-View)**, el cual es una variación directa del clásico patrón **MVC (Model-View-Controller)**. Este esquema separa las responsabilidades de la aplicación y trabaja de la mano con el principio **DRY (Don't Repeat Yourself)** para garantizar que no escribas código redundante.

Model (Modelo)

Define la estructura de los datos y las reglas de negocio. Se conecta a la Base de Datos mediante el ORM.

Template (Plantilla)

La capa de presentación (HTML con sintaxis Django). Es el equivalente a la Vista (View) en el MVC clásico.

View (Vista)

La lógica del servidor que recupera datos y llama al template. Equivale al Controlador (Controller) en MVC.

💡 Herencia de Componentes y Principio DRY

El principio DRY (Don't Repeat Yourself) promueve que cada pieza de conocimiento o lógica en un sistema sea única y libre de duplicación. En la interfaz de usuario, esto se logra mediante la **Herencia de Plantillas (Templates)** de Django:

1. Plantilla Base (`base.html`):

Define la estructura HTML común, enlaces de estilos, sidebar y header. Contiene bloques marcados con {% block content %}{% endblock %} que actúan como "huecos" a rellenar por páginas hijas.

2. Plantillas Hijas (Heredadas):

Declaran {% extends 'base.html' %} en su primera línea y reemplazan el contenido de los bloques individuales. De esta forma, si cambias el sidebar, se actualiza automáticamente en todo tu sitio web.
