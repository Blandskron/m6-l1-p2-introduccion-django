⚖️ Python Puro v/s Django Integrado

Para entender el valor real de Django, es útil compararlo con lo que tendríamos que hacer si programáramos un sitio web utilizando únicamente la librería estándar de Python (con sockets). Django abstrae la complejidad de bajo nivel del protocolo HTTP, automatizando tareas repetitivas y permitiéndonos escribir código limpio e intuitivo.

🔍 Comparador de Código Side-by-Side

Compara cómo se implementa un servidor básico que responde "Hola Mundo" en una ruta específica:

En Python puro, debes crear un Socket TCP, escuchar en un puerto, manejar hilos (threads) para conexiones simultáneas, parsear las cabeceras HTTP de forma manual y retornar la cabecera correcta concatenada con HTML:

import socket

server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
server.bind(('127.0.0.1', 8000))
server.listen(5)
# Bucle infinito para escuchar conexiones
while True:
    conn, addr = server.accept()
    request = conn.recv(1024).decode('utf-8')
    
    # Parsear cabeceras HTTP manualmente para enrutar
    lines = request.split('\n')
    first_line = lines[0]
    path = first_line.split(' ')[1] # Ej. '/contacto'
    
    if path == '/':
        html = "<html><body><h1>Hola Mundo</h1></body></html>"
        response = "HTTP/1.1 200 OK\r\nContent-Type: text/html\r\n\r\n" + html
    else:
        response = "HTTP/1.1 404 NOT FOUND\r\n\r\nPage Not Found"
        
    conn.sendall(response.encode('utf-8'))
    conn.close()

Con Django, el servidor socket y el parseo HTTP ya vienen resueltos por el framework. Solo defines la lógica de tu página en una Vista y la asocias a una ruta en URLs:

# 1. En views.py (La lógica o controlador)
from django.http import HttpResponse

def home(request):
    return HttpResponse("<h1>Hola Mundo</h1>")

# 2. En urls.py (El enrutador)
from django.urls import path
from . import views

urlpatterns = [
    path('', views.home, name='home'),
]
