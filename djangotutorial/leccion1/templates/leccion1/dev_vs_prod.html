⚙️ Entorno de Desarrollo v/s Producción

Uno de los mayores errores al desplegar aplicaciones empresariales es utilizar la misma configuración en desarrollo y en producción. Django está diseñado con la seguridad como máxima prioridad, por lo que proporciona variables específicas en `settings.py` para controlar el comportamiento del framework según el entorno en el que se ejecuta.

📊 Matriz de Configuración: Desarrollo v/s Producción

Compara cómo cambian los principales parámetros en el archivo settings.py al preparar un despliegue corporativo:

Variable / Característica 💻 Entorno de Desarrollo (Local) 🚀 Entorno de Producción (Servidor)
DEBUG True
Muestra páginas detalladas con trazas de error (Stack Trace) que revelan código fuente, bases de datos y variables de entorno. 		False
Desactiva las páginas de error interactivas. Muestra una página genérica 500/404. Esencial para no filtrar datos sensibles a atacantes.
ALLOWED_HOSTS [] o ['*']
Permite cualquier Host Header para facilitar el acceso en localhost (127.0.0.1). 		['www.miempresa.com', 'api.miempresa.com']
Filtra estrictamente qué dominios pueden enviar peticiones. Previene ataques de envenenamiento de Host HTTP (Host Header Injection).
SECRET_KEY Clave insegura por defecto o escrita en texto duro en settings.py. Cargada desde variables de entorno de forma segura:
os.environ.get('DJANGO_SECRET_KEY')
Nunca debe subirse a repositorios públicos como GitHub.
DATABASES SQLite3
Fácil de configurar. Almacenada en un solo archivo local (db.sqlite3). Ideal para un programador trabajando en solitario. 		PostgreSQL, MySQL o MariaDB
Servidor de base de datos independiente con alta concurrencia, transacciones rápidas y sistemas de réplica/respaldo continuos.
Archivos Estáticos Servidos automáticamente en tiempo real por el servidor de desarrollo runserver. Lento pero conveniente. Servidos por un servidor web dedicado (Nginx, Apache) o CDN (CloudFront, Cloudflare). Se recopilan ejecutando el comando:
python manage.py collectstatic

⚠️ Nota Crítica de Seguridad

Nunca expongas un servidor en producción con la variable DEBUG = True. Hacerlo permite a cualquier persona ajena a la organización visualizar el funcionamiento interno de tu base de datos, configuraciones, credenciales de correo electrónico, integraciones API y rutas del sistema al forzar una simple excepción de servidor.
